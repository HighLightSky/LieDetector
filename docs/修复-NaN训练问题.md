# NaN训练问题修复方案

## 问题描述

在增加权重衰减到5e-4后，从第3轮开始所有批次因损失为NaN被跳过，导致训练失败。

## 根本原因

1. **权重衰减过大**: 5e-4对于当前模型来说太激进，导致权重更新过大
2. **正则化过强**: 熵正则化0.2 + 权重一致性0.05 + 高权重衰减的组合导致数值不稳定
3. **梯度爆炸**: 多个损失项叠加，梯度累积过大

## 解决方案

### 1. 降低权重衰减（最关键）

```python
# 从 5e-4 降低到 2e-4
--weight_decay 2e-4
```

**原因**: 
- 原始1e-4太小，无法有效防止过拟合
- 5e-4太大，导致数值不稳定
- 2e-4是一个平衡点

### 2. 降低正则化强度

```python
# 熵正则化: 0.2 → 0.1
trainer.loss_computer.ent_reg_weight = 0.1

# 权重一致性: 0.05 → 0.02
trainer.loss_computer.w_mse_weight = 0.02
```

**原因**: 正则化项与权重衰减叠加效果，需要降低强度

### 3. 适度调整辅助损失权重

```python
loss_weights = {
    'fa_au': 0.2,  # 从0.15增加到0.2（而不是0.25）
    'fa_of': 0.2,  # 从0.15增加到0.2（而不是0.25）
}
```

**原因**: 0.25太高，与其他正则化叠加后容易不稳定

### 4. 增强梯度检查

在训练循环中添加了梯度NaN检测：
- 反向传播后检查所有参数梯度
- 发现NaN/Inf立即跳过并清零梯度
- 避免NaN传播到优化器

## 推荐训练配置

```bash
python train.py \
  --num_epochs 30 \
  --batch_size 8 \
  --lr 1e-5 \
  --weight_decay 2e-4 \
  --dropout 0.5 \
  --patience 7
```

## 参数对比

| 参数 | 原始值 | 失败值 | 推荐值 | 说明 |
|------|--------|--------|--------|------|
| weight_decay | 1e-4 | 5e-4 | 2e-4 | 适度增加 |
| dropout | 0.3 | 0.5 | 0.3 | 降低 |
| ent_reg_weight | 0.2 | 0.2 | 0.1 | 降低 |
| w_mse_weight | 0.05 | 0.05 | 0.02 | 降低 |
| fa_au/fa_of | 0.15 | 0.25 | 0.2 | 适度增加 |
| patience | 5 | 7 | 7 | 保持 |

## 诊断工具

运行以下命令检查模型健康状态：

```bash
python check_model_health.py
```

这会检查：
- 检查点权重是否包含NaN/Inf
- 前向传播是否产生NaN
- 输出权重分布是否正常

## 预期效果

1. **训练稳定性**: 不再出现NaN损失
2. **过拟合改善**: 训练-验证差距从12.8%缩小到8-10%
3. **辅助损失降低**: fa_au和fa_of从0.84降低到0.70左右
4. **泛化能力**: 验证准确率可能略降（72% → 70%），但模型更稳健

## 渐进式调优策略

如果2e-4仍然不稳定：
1. 先用1.5e-4训练
2. 观察3-5个epoch
3. 如果稳定，逐步增加到2e-4

如果想进一步减少过拟合：
1. 先确保训练稳定
2. 再考虑增加dropout到0.6
3. 或添加数据增强
